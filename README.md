## How I approach incidents

1. **Verify identity and authorization** following the simulated company's security requirements.
2. **Assess impact and priority** by identifying affected users, services, and business operations.
3. **Consult the Knowledge Base** and follow documented procedures rather than guessing.
4. **Investigate systematically** with the tools provided, such as Active Directory, Remote Desktop, Server Room, and email administration.
5. **Apply and validate a fix** with the end user whenever possible.
6. **Document the work** with symptoms, investigation, actions, outcomes, and remaining uncertainty.

## Skills practiced

- **User and account administration:** Active Directory, account attribute updates, email alias retention
- **Remote support:** remote workstation access, VPN connectivity, shared-drive troubleshooting
- **Endpoint troubleshooting:** video drivers, display issues, initial power diagnostics
- **Infrastructure support:** print server recovery, network switch outage isolation, service restoration
- **ITSM fundamentals:** ticket handling, prioritization, knowledge-base use, user communication, resolution notes

## Case study structure

Each file includes the reported issue, relevant context, actions performed, outcome and evidence, technical interpretation, and learning points. I avoid claiming root causes when only service recovery has been demonstrated.
